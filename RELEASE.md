# Release Notes: `gateway-client` v0.2.0 (`v0.1.1` / `b4b05a2` → `197f3b8`)

`gateway-client` `0.2.0` (`197f3b8:pyproject.toml:7`, `197f3b8:gateway_client/__init__.py:24`) implements **service contract version 2** (`CONTRACT_VERSION = 2` at `197f3b8:gateway_client/protocol.py:19` and `197f3b8:gateway_client/e2e.py:79`) and GW-3 per-call caller-token verification (`197f3b8:gateway_client/caller_token.py:1-41`). It adds runtime dependency `PyJWT[crypto]>=2.8,<3` (`197f3b8:pyproject.toml:16`, `197f3b8:gateway_client/caller_token.py:55`).

This is a **breaking release**: a contract v2 gateway refuses v1 registrations (`0.1.x`) with `unsupported_contract`, and `0.2.0` registers exclusively with `contract_version: 2` (`197f3b8:gateway_client/protocol.py:7-9`, `197f3b8:gateway_client/protocol.py:78-89`).

---

## 1. Service-Name Rules (`SERVICE_NAME` / `service_name`)

- **Required non-empty string at startup (`ConfigError`)**: `Config.load` strips `service_name` / `SERVICE_NAME` (`197f3b8:gateway_client/config.py:55`) and raises `ConfigError("SERVICE_NAME and SERVICE_CREDENTIAL are required (gateway service contract version 2).")` if either is missing or whitespace-only (`197f3b8:gateway_client/config.py:57-59`, `197f3b8:gateway_client/errors.py:35-36`).
- **Sent as `service` in contract v2 `register` frames**: `GatewayService._register_frame` passes `self.config.service_name` to `Declaration.register`, which sends `"service": service` on the wire (`197f3b8:gateway_client/service.py:328-330`, `197f3b8:gateway_client/protocol.py:78-89`).
- **Strict `caller_token` `aud` equality (list `aud` refused)**: `GatewayService.__init__` initializes `CallerTokenVerifier(self.config.service_name, ...)` (`197f3b8:gateway_client/service.py:178-182`, `197f3b8:gateway_client/caller_token.py:220-223`). Every `call` and `read_resource` must carry a `caller_token` whose `aud` claim is a `str` strictly equal to `self.config.service_name`; `CallerTokenVerifier._decode` checks `audience=self.audience` (`197f3b8:gateway_client/caller_token.py:270-274`, `197f3b8:gateway_client/caller_token.py:279-280`) and `CallerTokenVerifier._check_claims` enforces `claims.get("aud") != self.audience` (`197f3b8:gateway_client/caller_token.py:285-286`), refusing a list `aud` with `not_allowed` even if it contains `self.config.service_name` (`197f3b8:gateway_client/caller_token.py:20-21`, `197f3b8:tests/test_caller_token.py:89-98`).
- **End-to-end associated data `service` comes from verified token `aud`, never the frame**: In `end-to-end` mode, `GatewayService._reply` sets the HPKE associated-data `service` field to `verified.claims["aud"]` (verified equal to `self.config.service_name`) rather than `frame.get("service")` (`197f3b8:gateway_client/service.py:579-582`, `197f3b8:gateway_client/e2e.py:191-205`, `197f3b8:tests/test_service.py:508-520`).
- **Legacy `BACKEND_ID` and `WN_BACKEND_TOKEN` removed (`TypeError` if passed as kwargs)**: `Config.backend_id`, `Config.legacy_backend_id`, and `Config.legacy_token` are removed (were `b4b05a2:gateway_client/config.py:38-43`; `197f3b8:tests/test_config.py:44-51`). Passing `backend_id=` or `legacy_token=` to `Config.load(...)` or `GatewayService(...)` now raises `TypeError` (`197f3b8:gateway_client/config.py:46-51`, `197f3b8:gateway_client/service.py:173-176`).
- **Passing both `config=` and configuration keyword arguments raises `TypeError`**: `GatewayService.__init__` now raises `TypeError("pass either config or configuration keyword arguments, not both ...")` if `config` is provided alongside keyword arguments such as `service_name=` (`197f3b8:gateway_client/service.py:173-175`), instead of silently ignoring the keyword arguments as in `v0.1.1`.

## 2. `caller_token` Shape, Verification, JWKS, and `Caller` Identity

### 2.1 Wire `caller_token` shape and verification rules (`GW-3`, `INT-C3`)

- **Verified first on every `call` and `read_resource`**: `GatewayService._reply` calls `await self._verify_caller(frame)` on `frame.get("caller_token")` before checking encryption mode, `client_public_key`, target tool/resource declaration, or running `on_call` / `on_read` (`197f3b8:gateway_client/service.py:537-548`, `197f3b8:gateway_client/service.py:550-568`). Any frame-level identity fields (`caller`, `principal`, `user_id`, `sub`, `service`) are ignored (`197f3b8:gateway_client/service.py:568-583`, `197f3b8:tests/test_service.py:437-449`).
- **Compact JWS with `alg: "EdDSA"` and non-empty `kid`**: `CallerTokenVerifier.verify` requires `token` to be a non-empty `str` (`197f3b8:gateway_client/caller_token.py:247-248`), parseable as a JWT header (`197f3b8:gateway_client/caller_token.py:249-252`), with `header.get("alg") == "EdDSA"` (`ALGORITHM = "EdDSA"`, `197f3b8:gateway_client/caller_token.py:59`, `197f3b8:gateway_client/caller_token.py:253-254`) and a non-empty `str` `kid` (`197f3b8:gateway_client/caller_token.py:255-257`).
- **Ed25519 signature against the gateway JWKS**: `kid` is looked up via `await self.key_set.key(kid)` (`197f3b8:gateway_client/caller_token.py:197-214`, `197f3b8:gateway_client/caller_token.py:258`), which only accepts JWKS entries with `kty == "OKP"`, `crv == "Ed25519"`, and non-empty `str` `kid` (`197f3b8:gateway_client/caller_token.py:117-132`). `CallerTokenVerifier._decode` verifies the EdDSA signature (`197f3b8:gateway_client/caller_token.py:268-276`).
- **Required claims (`sub`, `act`, `aud`, `exp`, `jti`)**: `REQUIRED_CLAIMS = ("sub", "act", "aud", "exp", "jti")` are required at decode time (`197f3b8:gateway_client/caller_token.py:60`, `197f3b8:gateway_client/caller_token.py:273-278`) and validated in `CallerTokenVerifier._check_claims` (`197f3b8:gateway_client/caller_token.py:284-297`):
  - `sub` (principal WRN), `act` (connected app WRN), and `jti` (token ID) must each be a non-empty, non-blank `str` (`not isinstance(value, str) or not value.strip()`, `197f3b8:gateway_client/caller_token.py:287-290`).
  - `aud` must be a `str` equal to `self.audience` (`self.config.service_name`) (`197f3b8:gateway_client/caller_token.py:279-280`, `197f3b8:gateway_client/caller_token.py:285-286`).
  - `exp` must be an `int` or `float` (`isinstance(exp, bool) or not isinstance(exp, (int, float))` is refused, `197f3b8:gateway_client/caller_token.py:291-293`), must not be expired beyond `leeway` (`exp + self._leeway < now`, default `DEFAULT_LEEWAY_SECONDS = 10`, `197f3b8:gateway_client/caller_token.py:62`, `197f3b8:gateway_client/caller_token.py:294-295`), and must not exceed the 60-second maximum token lifetime plus `leeway` (`exp - now > MAX_TTL_SECONDS + self._leeway`, `MAX_TTL_SECONDS = 60`, `197f3b8:gateway_client/caller_token.py:61`, `197f3b8:gateway_client/caller_token.py:296-297`).
  - `jti` must not have been seen in the in-memory replay cache `self._seen` (`197f3b8:gateway_client/caller_token.py:227-241`, `197f3b8:gateway_client/caller_token.py:261-264`). Accepted `jti` entries are held until `float(claims["exp"]) + self._leeway` (`197f3b8:gateway_client/caller_token.py:264`) and purged at most once per second (`197f3b8:gateway_client/caller_token.py:234-241`).
- **Token refusal error codes (`not_allowed` vs `unavailable`) and logging**:
  - Any token check failure raises `TokenRefused(reason, code="not_allowed")` (`197f3b8:gateway_client/caller_token.py:74-82`), logged once at `WARNING` with the check reason and never the token or claim values (`197f3b8:gateway_client/service.py:544-546`), and answered with `code: "not_allowed"` and `payload: "caller token refused"` (`TOKEN_REFUSED`, `197f3b8:gateway_client/service.py:62`, `197f3b8:gateway_client/service.py:547-548`).
  - If the JWKS cannot be fetched on initial load (`self._loaded_at is None`), or a fetch fails and the token's `kid` is not cached — either a refresh of a key set older than `max_age` or a refetch triggered by an unknown `kid` (`outcome == FAILED`) — `KeySet.key` raises `TokenRefused("the gateway key set could not be fetched", UNAVAILABLE)` (`197f3b8:gateway_client/caller_token.py:202-213`), answered with `code: "unavailable"` and `payload: "caller token could not be checked; retry"` (`TOKEN_UNCHECKED`, `197f3b8:gateway_client/service.py:63`, `197f3b8:gateway_client/service.py:547-548`).
  - In `end-to-end` mode, a token refusal happens before `client_key` and associated-data `fields` are constructed (`197f3b8:gateway_client/service.py:565-583`), so the error reply is sent unsealed (`197f3b8:gateway_client/service.py:555-558`, `197f3b8:gateway_client/service.py:616-624`); the gateway relays an unsealed `end-to-end` backend reply to the client as `internal` (`197f3b8:tests/test_service.py:523-535`).

### 2.2 JWKS discovery, caching, and configuration

- **JWKS URL derivation and override**: By default, `Config.key_set_url` (`197f3b8:gateway_client/config.py:40-43`) derives the JWKS URL from `Config.url` (`GATEWAY_BACKEND_URL`) via `jwks_url_for`: `wss://` becomes `https://`, `ws://` becomes `http://`, and a trailing `/backend` is replaced with `/.well-known/jwks.json` (`JWKS_PATH`, `197f3b8:gateway_client/caller_token.py:67`, `197f3b8:gateway_client/caller_token.py:95-104`). It can be overridden via `GATEWAY_JWKS_URL` or `jwks_url=` (`197f3b8:gateway_client/config.py:38`, `197f3b8:gateway_client/config.py:49`, `197f3b8:gateway_client/config.py:64-66`), which must start with `https://` or `http://` (`197f3b8:gateway_client/config.py:65-66`).
- **HTTP bounds and key-set cache behavior**: `fetch_jwks` uses a 5.0 s timeout (`FETCH_TIMEOUT_SECONDS = 5.0`, `197f3b8:gateway_client/caller_token.py:65`, `197f3b8:gateway_client/caller_token.py:107-110`) and rejects responses over 64 KiB (`MAX_JWKS_BYTES = 64 * 1024`, `197f3b8:gateway_client/caller_token.py:66`, `197f3b8:gateway_client/caller_token.py:111-113`). `KeySet` caches keys for `DEFAULT_MAX_AGE_SECONDS = 3600.0` (1 hour, `197f3b8:gateway_client/caller_token.py:64`, `197f3b8:gateway_client/caller_token.py:159-160`), retains cached keys if a refresh fails (`197f3b8:gateway_client/caller_token.py:189-192`, `197f3b8:gateway_client/caller_token.py:202-205`), rate-limits refetches (including on unknown `kid`) to once per `DEFAULT_MIN_REFETCH_SECONDS = 10.0` (`197f3b8:gateway_client/caller_token.py:63`, `197f3b8:gateway_client/caller_token.py:155-157`, `197f3b8:gateway_client/caller_token.py:208-211`), and coalesces concurrent fetches with an `asyncio.Lock` and generation counter (`197f3b8:gateway_client/caller_token.py:176-195`).
- **`GatewayService` parameters and exports**: `GatewayService.__init__` accepts `jwks_fetch`, `token_leeway`, `jwks_min_refetch_interval`, and `jwks_max_age` and exposes `service.jwks_url` (`197f3b8:gateway_client/service.py:168-172`, `197f3b8:gateway_client/service.py:178-182`, `197f3b8:gateway_client/service.py:218-221`). `CallerTokenVerifier`, `KeySet`, `TokenRefused`, and `VerifiedToken` are exported from `gateway_client` (`197f3b8:gateway_client/__init__.py:5`, `197f3b8:gateway_client/__init__.py:29-31`).

### 2.3 Breaking changes to `Caller` and `end-to-end` binding

- **`Caller.user_id` and `Caller.client_id` removed**: Replaced on `Caller` (`197f3b8:gateway_client/service.py:66-94`, `197f3b8:tests/test_service.py:215-219`) by:
  - `caller.principal: str` — verified token `sub` (principal WRN, always a non-blank `str`, `197f3b8:gateway_client/service.py:81`).
  - `caller.app: str` — verified token `act` (connected app WRN, always a non-blank `str`, `197f3b8:gateway_client/service.py:82`).
  - `caller.token: str` — raw verified compact JWT (`repr=False`, for forwarding only; never logged, `197f3b8:gateway_client/service.py:85`).
  - `caller.claims: Any` — verified JWT claims (`repr=False, compare=False`, default `None`, `197f3b8:gateway_client/service.py:86`). A `Caller` passed to `on_call` / `on_read` is built by `Caller.from_token`, so `claims` is a read-only `MappingProxyType` (`197f3b8:gateway_client/service.py:88-93`, `197f3b8:gateway_client/caller_token.py:265-266`); a `Caller` constructed directly (e.g. in tests) has `claims=None` unless one is passed.
  - `caller.encryption: str` and `caller.request_id: str | None` are unchanged (`197f3b8:gateway_client/service.py:83-84`).
- **End-to-end associated data, replay guard, and downgrade pin use verified token WRNs**:
  - `e2e.CONTRACT_VERSION` is `2` (`197f3b8:gateway_client/e2e.py:79`); `e2e.header` builds `{contract_version: 2, user_id, client_id, service, encryption, tool|uri}` (`197f3b8:gateway_client/e2e.py:191-205`).
  - `GatewayService._reply` populates `e2e.header(user_id=caller.principal, client_id=caller.app, service=verified.claims["aud"], ...)` (`197f3b8:gateway_client/service.py:579-582`). An envelope sealed under any other `user_id`, `client_id`, `service`, or `contract_version` fails AEAD authentication and is refused with `bad_arguments` (`197f3b8:gateway_client/e2e.py:301-310`, `197f3b8:tests/test_service.py:508-520`).
  - The 10-minute E2E nonce replay window (`self._replay.claim`, `197f3b8:gateway_client/e2e.py:84`, `197f3b8:gateway_client/e2e.py:262-283`, `197f3b8:gateway_client/service.py:588-591`) and the in-memory plaintext-downgrade pin (`self._pinned`, `197f3b8:gateway_client/service.py:190`, `197f3b8:gateway_client/service.py:484-491`, `197f3b8:gateway_client/service.py:583`, `197f3b8:gateway_client/service.py:594`) are keyed per connected app WRN (`caller.app` / token `act`) instead of v1 `client_id`.

## 3. Registration & Registration Refusals

### 3.1 Contract v2 `register` frame and removal of `roles` / `roles_version`

- **Contract v2 `register` payload**: `Declaration.register(service, credential, public_key)` (renamed from `v1_register`, `b4b05a2:gateway_client/protocol.py:125`) sends `{type: "register", contract_version: 2, service, credential, public_key, accepts_caller: True, tools, resources}` (`197f3b8:gateway_client/protocol.py:19`, `197f3b8:gateway_client/protocol.py:78-89`, `197f3b8:gateway_client/service.py:328-330`). While registered, `service.mode` is `"v2"` (`MODE_V2 = "v2"`, `197f3b8:gateway_client/service.py:59`, `197f3b8:gateway_client/service.py:214-216`, `197f3b8:gateway_client/service.py:392-393`).
- **`roles` and `roles_version` removed (`TypeError` if passed)**: `Declaration` (`197f3b8:gateway_client/protocol.py:30-62`), `GatewayService.__init__` (`197f3b8:gateway_client/service.py:161-177`), and `GatewayService.update` (`197f3b8:gateway_client/service.py:273-291`) no longer accept `roles` or `roles_version`. Passing `roles=` or `roles_version=` to `GatewayService(...)` or `service.update(...)` raises `TypeError` (`197f3b8:tests/test_service.py:97-102`).
- **Role-based helpers and local `requires_end_to_end` tool check removed**: `Declaration.e2e_only()`, `Declaration.role_set()`, and `Declaration.check_successor()` are removed (were `b4b05a2:gateway_client/protocol.py:98-123`). Under contract v2, tool permissions and `requires_end_to_end` are configured in `wolf-access` and enforced by the gateway before routing (`197f3b8:gateway_client/service.py:484-491`).

### 3.2 Local startup and declaration refusals (before wire registration)

- **Configuration refusals (`ConfigError` / `TypeError`)**:
  - Missing or blank `SERVICE_NAME` / `service_name` or `SERVICE_CREDENTIAL` / `credential` raises `ConfigError` (`197f3b8:gateway_client/config.py:55-59`).
  - `GATEWAY_BACKEND_URL` / `url` not starting with `ws://` or `wss://` raises `ConfigError` (`197f3b8:gateway_client/config.py:60-61`).
  - `GATEWAY_JWKS_URL` / `jwks_url` (when set) not starting with `https://` or `http://` raises `ConfigError` (`197f3b8:gateway_client/config.py:64-66`).
  - Invalid `SERVICE_PRIVATE_KEY` / `private_key` (not base64url 32-byte X25519 key) or unreadable/invalid/uncreatable `SERVICE_PRIVATE_KEY_FILE` / `private_key_file` raises `ConfigError` (`197f3b8:gateway_client/config.py:75-81`, `197f3b8:gateway_client/config.py:99-110`).
  - Passing both `config=` and any configuration keyword argument to `GatewayService(...)`, or passing removed `roles=`, `roles_version=`, `legacy_token=`, or `backend_id=`, raises `TypeError` (`197f3b8:gateway_client/config.py:46-51`, `197f3b8:gateway_client/service.py:161-176`, `197f3b8:gateway_client/service.py:273-275`).
- **Local declaration validation refusals (`ValueError` in `Declaration.build`)**:
  - Validated at `GatewayService.__init__` (`197f3b8:gateway_client/service.py:177`) and `GatewayService.update` (`197f3b8:gateway_client/service.py:287-288`):
    - Tool missing non-empty `str` `name`, `str` `description`, or `dict` `inputSchema` raises `ValueError("tools[i] needs name, description and inputSchema")` (`197f3b8:gateway_client/protocol.py:44-48`).
    - A tool may also carry an optional `annotations` object (MCP tool annotations: `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`); `Declaration.build` keeps it and the `register` frame sends it unchanged. The gateway rejects a non-object `annotations` with `malformed_tool`.
    - Duplicate tool `name` raises `ValueError("tool <name> declared twice")` (`197f3b8:gateway_client/protocol.py:49-51`).
    - Resource missing non-empty `str` `uri`, `str` `name`, `str` `mimeType`, or `str` `description` raises `ValueError("resources[i] needs uri, name, mimeType and description")` (`197f3b8:gateway_client/protocol.py:53-58`).
    - Duplicate resource `uri` raises `ValueError("resource <uri> declared twice")` (`197f3b8:gateway_client/protocol.py:59-61`).

### 3.3 Wire registration refusals (`rejected`), backoff, and removal of legacy fallback

- **Contract version mismatch (`unsupported_contract`)**: A contract v2 gateway refuses a v1 `register` frame with `{"type": "rejected", "reason": "unsupported_contract"}`, (`197f3b8:gateway_client/protocol.py:7-9`, `197f3b8:CHANGELOG.md:8-11`, `197f3b8:tests/test_integration.py:29-31`). `0.2.0` cannot connect to a gateway that speaks only version 1 (`197f3b8:CHANGELOG.md:10-11`); the reason such a gateway answers with is not specified here.
- **Initial registration `rejected` handling and 300 s backoff**: When `_first_reply` receives `{"type": "rejected", "reason": ...}` (`197f3b8:gateway_client/service.py:349-350`, `197f3b8:gateway_client/service.py:387-388`), `GatewayService.run` logs `registration rejected: <reason>; retrying with backoff up to 300 s` at `ERROR` once per distinct consecutive reason (`197f3b8:gateway_client/service.py:246-250`) and sleeps using `Backoff.next_delay(rejected=True)` capped at `REJECTED_CAP_SECONDS = 300.0` (5 minutes, with up to 50% random jitter) instead of `RETRY_CAP_SECONDS = 30.0` (`197f3b8:gateway_client/protocol.py:21-23`, `197f3b8:gateway_client/protocol.py:131-135`, `197f3b8:gateway_client/service.py:254-255`). Gateway rejection reasons include `unsupported_contract`, `bad_credential`, `key_changed` (if the service restarts with a new X25519 key after the gateway pinned its first `public_key`, `197f3b8:gateway_client/config.py:86-94`), `missing_field`, and `malformed_tool` (`197f3b8:tests/test_integration.py:25-41`, `197f3b8:tests/test_service.py:121`, `197f3b8:tests/test_service.py:163`).
- **No legacy protocol fallback on close without reply**: `Declaration.legacy_register`, `MODE_LEGACY`, and `GatewayService._reply_legacy` are removed (were `b4b05a2:gateway_client/protocol.py:139-141`, `b4b05a2:gateway_client/service.py:56`, `b4b05a2:gateway_client/service.py:618`; `197f3b8:gateway_client/protocol.py:9`). If the gateway closes the connection without replying to `register` (or does not reply within `DEFAULT_REPLY_TIMEOUT = 30.0` s, `197f3b8:gateway_client/service.py:61`, `197f3b8:gateway_client/service.py:343-348`), the service logs a warning and retries contract v2 with backoff up to `RETRY_CAP_SECONDS = 30.0` (`197f3b8:gateway_client/service.py:251-255`).
- **Live re-registration refusal (`RegistrationRejected` on `service.update()`)**: If `await service.update(tools=..., resources=...)` receives `{"type": "rejected", "reason": ...}` on an established connection (`197f3b8:gateway_client/service.py:306-310`), it restores `self._decl = old`, records `self._rejected_on_update = reason` so the outer loop uses the 300 s `rejected` backoff cap after disconnect (`197f3b8:gateway_client/service.py:356-358`), and raises `RegistrationRejected(reason)` (`197f3b8:gateway_client/errors.py:39-45`).

## 4. Backend Author Migration Checklist (`0.1.1` → `0.2.0`)

1. **Confirm the gateway speaks contract v2 before deploying `0.2.0`**. `0.2.0` cannot connect to a gateway that speaks only version 1, and has no legacy-protocol fallback: a `0.1.1` service that relied on `WN_BACKEND_TOKEN` to reach a pre-contract gateway loses its connection after upgrading (`197f3b8:CHANGELOG.md:8-11`, see 3.3).
2. **Remove `roles` and `roles_version`** from `GatewayService(...)` and `await service.update(...)` (`197f3b8:gateway_client/service.py:161-177`, `197f3b8:gateway_client/service.py:273-291`); move tool permissions and `requires_end_to_end` policies to `wolf-access`.
3. **Update `Caller` attribute access** in `on_call` and `on_read` from `caller.user_id` / `caller.client_id` to `caller.principal` (token `sub` WRN) and `caller.app` (token `act` WRN), and use `caller.token` / `caller.claims` where downstream forwarding or claim inspection is needed (`197f3b8:gateway_client/service.py:66-94`, `197f3b8:examples/selftest_service.py:29-33`).
4. **Verify `SERVICE_NAME` matches token `aud`** issued by the gateway (`197f3b8:gateway_client/config.py:55-59`, `197f3b8:gateway_client/caller_token.py:285-286`), and remove `WN_BACKEND_TOKEN` / `BACKEND_ID` (were `b4b05a2:gateway_client/config.py:38-43`, `b4b05a2:gateway_client/config.py:64-65`).
5. **Ensure HTTP(S) reachability to the gateway's JWKS** at `<gateway>/.well-known/jwks.json` or configure `GATEWAY_JWKS_URL` / `jwks_url=` (`197f3b8:gateway_client/caller_token.py:95-114`, `197f3b8:gateway_client/config.py:40-43`, `197f3b8:gateway_client/config.py:64-66`).
6. **Do not combine `config=` with configuration keyword arguments** in `GatewayService(...)` (`197f3b8:gateway_client/service.py:173-175`).
